# T01 직접 채우기 가이드

`index.html`에서 **[직접 입력]**을 검색하면 수정할 곳을 빠르게 찾을 수 있습니다.

## 꼭 한 번 확인할 부분

### 1. 경험 01 — 자동화
현재 문장 아래에 아래 내용을 넣을 수 있습니다.
- 실제 사용 기술
- 프로그램이 어떤 방식으로 실행됐는지
- 가장 크게 줄어든 반복 작업

예시 형식:
> Python과 YouTube API를 이용해 댓글 수집 과정을 자동화했고, 팀원이 직접 실행할 수 있도록 사용 방법과 함께 공유했습니다.

### 2. 경험 02 — DB 설계
아래 중 실제 사실에 맞는 것을 1~2문장으로 넣습니다.
- 맡았던 테이블/데이터 구조
- 프론트엔드·백엔드와 맞춘 방식
- 요구사항이 바뀌었을 때 수정한 내용

### 3. 경험 03 — 문제 해결
아래 중 하나를 추가하면 좋습니다.
- 오류를 발견한 로그
- 인증서 경로/권한 문제를 어떻게 확인했는지
- 해결 후 문서화하거나 공유한 내용

### 4. 관심 기술/자격
실제로 공부했거나 보유한 것만 남깁니다.
현재 기본 표시는 Network / Linux / Database / Security / Cloud / Python 입니다.
원하면 `index.html`의 `<div class="tag-list">` 안의 `<span>`을 추가·삭제하면 됩니다.

### 5. 내 말로 소개하는 나
이 부분은 AI 문장보다 **본인의 말투가 드러나는 문장**을 넣는 것을 권장합니다.
2~4문장이 적당합니다.

작성 예시 틀:
> 저는 [어떤 상황]에서 [어떤 방식]으로 움직이는 사람입니다.  
> 특히 [관심/태도]를 중요하게 생각하고, 최근에는 [요즘 배우는 것/관심사]에 관심을 두고 있습니다.

### 6. 공개 가능한 근거
T01-C09를 더 확실하게 만족하려면 실제 확인 가능한 근거를 1개 이상 연결하는 것이 좋습니다.

후보:
- 공개 GitHub 프로젝트 README
- 개인정보를 제거한 프로젝트 결과 화면
- 프로그램 실행 화면
- 문제 해결 과정을 정리한 공개 문서

**주의:** 임시 `#` 링크나 존재하지 않는 URL은 넣지 마세요. T01-C13에서 모든 링크가 실제 선언한 주소로 열려야 합니다.

### 7. 취향
실링왁스·키링·수영·배드민턴 문장은 현재 알고 있는 내용을 바탕으로 작성되어 있습니다.
더 개인적인 느낌을 주고 싶으면 요즘 좋아하는 것 또는 수집하는 것을 한 문장 추가하면 됩니다.

## 최종 제출 전 반드시 할 일
1. 브라우저에서 `[직접 입력]`이라는 글자가 남아 있지 않은지 검색합니다.
2. 채우지 않을 영역은 해당 `<div class="fill-slot"> ... </div>` 전체를 삭제합니다.
3. 전화번호, 개인 이메일, 상세 주소 등 공개하지 않기로 한 정보가 없는지 확인합니다.
4. GitHub에 비밀번호, 토큰, API Key, `.env` 파일을 올리지 않습니다.
5. 공개 URL의 모든 링크를 새 시크릿 창에서 다시 눌러봅니다.
