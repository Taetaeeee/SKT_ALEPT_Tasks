### T01 · 자기소개 페이지

> 공개할 정보와 공개하지 않을 정보를 먼저 나누고, 강점의 근거와 접근성을 함께 검증하는 1페이지 웹사이트

공개 범위를 먼저 정한 뒤 강점과 경험을 **상황·행동·결과**로 정리하고, 다른 사람이 확인할 수 있는 공개 근거를 연결했습니다. 두 기준 해상도와 키보드 접근성, 명암, 제목 구조, 링크, 콘솔 오류 등을 직접 검사하고 발견한 결함을 수정했습니다.

**주요 내용**
- 공개할 정보와 공개하지 않을 정보 구분 및 개인정보 점검
- 강점·취향 3개의 상황·행동·결과와 공개 가능한 근거 연결
- 1366×768 / 1920×1080 기준 첫 화면과 가로 넘침 검증
- 링크·Tab 이동·제목 단계·텍스트 대비·콘솔 오류 검사
- 실제 결함 3건 이상의 수정 전후 기록
- 마우스와 키보드에서 동일하게 동작하는 상호작용 구현
- 움직임 감소 선택권과 비밀번호·토큰·API 키 노출 점검

**링크:** [🌐 페이지 실행](https://taetaeeee.github.io/SKT_ALEPT_Tasks/T01_onepagemyself/) · [📁 소스 코드](./T01_onepagemyself/)

### T02 · 암호 해제 미니게임

> 짧은 시간 안에 한 판이 끝나고, 입력·시간·저장 상태가 안정적으로 유지되는 반응형 웹 게임

25초 제한시간 동안 코드를 입력해 목표를 달성하는 미니게임입니다. 단순 플레이뿐 아니라 연속 입력, 화면 크기 변경, 포커스 이탈, 일시정지, 장시간 실행을 확인했습니다. 난이도 값 하나만 바꾼 10회 전후 기록을 비교해 최종 설정을 선택했습니다.

**주요 내용**
- 게임 규칙·핵심 조작·현재 상태를 한 화면에서 확인
- 성공·실패 뒤 재시작 시 현재 판 상태 초기화
- 1366×768 / 1920×1080 화면 및 가로 넘침 검증
- 1초 안의 연속 입력 10건, 창 크기 변경, 포커스 복귀, 일시정지 검증
- 10분 연속 실행과 콘솔 오류 점검
- 난이도 값 하나만 변경한 10회 + 10회 플레이 기록 비교
- 새 게임 초기화와 재접속 보존값 분리
- 빈 저장값·손상 저장값의 기본값 복구
- 효과 발생 조건과 음소거 또는 움직임 감소 선택권 검증

**링크:** [🌐 게임 실행](https://taetaeeee.github.io/SKT_ALEPT_Tasks/T02_code_break/) · [📁 소스 코드](./T02_code_break/)

### T03 · 밈 만들기

> 이미지와 한글 문구를 편집하고, 미리보기와 저장 파일의 결과까지 검증하는 웹 이미지 편집 도구

PNG·JPEG 이미지를 불러와 여러 문구의 위치·크기·색상·각도를 조절하고 PNG로 저장할 수 있도록 구현했습니다. 세 가지 화면비에서 미리보기와 저장 파일을 대조하고, 극단 입력·템플릿 CRUD·JSON 백업/복원까지 확인했습니다.

**주요 내용**
- PNG·JPEG 불러오기, Drag & Drop, 지원하지 않는 파일 안전 거부
- 다중 문구의 위치·크기·색상·회전과 실시간 미리보기
- 이미지 위치 조절 기능과 편집 상태 보존
- 1:1·4:5·9:16 화면비의 미리보기/저장 파일 일치 검증
- 긴 글·영문 혼합·줄바꿈·이모지·빈 문구·가로/세로/투명 이미지 등 극단 입력 12건 검사
- 템플릿 3개 이상의 생성·불러오기·수정·삭제와 새로고침 보존
- 정상·손상·필수 항목 누락 JSON 가져오기 검증
- 서로 다른 완성 이미지 3개와 위치 정보 메타데이터 제거 확인

### T04 · 생활 환율

> 실제 공개 원천의 환율을 조회하고, 출처·시간·실패 상태·날짜별 변화를 함께 확인하는 정보 보드

USD·JPY·CNY 환율을 공개 데이터에서 조회하고 값·단위·출처·원천 시각·조회 시각·기준 시간대를 표시했습니다. 외부 응답 실패 시 마지막 정상값을 유지하고, 합성 실패 시나리오와 실제 서로 다른 KST 날짜 2건을 이용해 복구 및 전일 대비 계산을 검증했습니다.

**주요 내용**
- 비밀키 없이 실제 공개 원천의 동적 환율 조회
- 값·단위·출처·원천 관측 시각·조회 시각·기준 시간대 표시
- 정상 응답의 원자료·저장값·화면값 일치 확인
- Timeout·401/403·429·오프라인·응답 형식 변경의 5가지 실패 재현
- 실패 시 마지막 정상값 유지, stale 표시, 다시 시도 후 fresh 복구
- Asia/Seoul 날짜 기준 같은 날 중복 기록 방지
- 서로 다른 실제 KST 날짜 2건 보존 및 전일 대비 변화 재계산
- 합성 시험값과 실제 기록 분리, 개인정보·비밀값 노출 점검

### T05 · AI 협업 및 인수인계

> 같은 문제와 같은 검사를 기준으로 AI A의 중간 작업을 AI B가 대화 없이 이어받아 완성하는 인수인계 실험

T03 기능 개선을 대상으로 작업 전에 **고정 검사 10개**와 공통 시간·요청 상한을 정했습니다. AI A의 중간 상태를 저장소 버전과 7개 항목의 인수인계 문서로 남기고, AI B에는 기존 대화 없이 저장소와 인수인계 문서만 제공해 같은 검사를 이어서 수행했습니다.

**주요 내용**
- 작업 시작 전 ID·입력·관찰 가능한 기대값이 있는 검사 10개 고정
- AI A/B에 동일한 시간 상한과 요청·호출 수 상한 적용
- `AI A 시작 → AI A 종료·인수인계 → AI B 시작 → AI B 종료` 순서 기록
- AI A의 저장소 버전·검사 결과·남은 문제 보존
- 목표·현재 상태·실행 명령·통과 검사·남은 문제·다음 행동·건드리지 말 것의 7항목 인수인계
- 새 작업 폴더에서 실행 명령 재현
- AI B에는 저장소와 인수인계 문서만 제공하고 동일한 10개 검사 유지
- 두 AI의 시간·요청/호출 수·오류 회차·검사 통과 수를 이름을 가리고 비교

**링크:** [📊 결과 보고서](https://taetaeeee.github.io/SKT_ALEPT_Tasks/T05_handoff_project/report.html) · [📁 소스 코드](./T05_handoff_project/)

### T06 · 계획·실행 다이어리

> 계획한 일과 실제로 수행한 일을 분리해 기록하고, 차이를 다음 계획에 반영하는 PLAN·DO·SEE 웹 애플리케이션

Cloudflare Workers와 D1(SQLite)을 사용해 계획, 할 일, 실행 기록, 돌아보기를 서버 데이터베이스에 저장하도록 구현했습니다. 계획 수정 전 내용을 보존하고, 실제 소요시간과 막힌 이유를 계획값과 별도로 기록하며, 집계 숫자에서 근거 기록까지 다시 확인할 수 있게 구성했습니다.

**주요 내용**
- 계획의 기간·우선순위·성공 기준·예상 시간 저장
- 계획 수정 전 스냅샷을 별도 이력으로 보존
- 할 일 생성·수정·완료·되돌리기·삭제와 마감일·우선순위·태그·예상 시간 관리
- 검색·필터·정렬 및 정렬 기준 표시
- 시작 시각·종료 시각·실제 소요시간·막힌 이유를 실행 기록으로 별도 저장
- 완료 버튼 중복 실행에도 완료 기록과 집계가 한 번만 반영되도록 처리
- 계획 수·완료 수·지연 수·막힘 수·예상/실제 시간·차이 집계
- 집계 숫자에서 근거 기록으로 이동하고 개선점 한 건을 다음 계획으로 전달
- 실제 계획 1개 이상·할 일 5개 이상·실행 기록 3개 이상으로 사용 검증
- D1 데이터 보존, 새로고침 복원, 전체 데이터 JSON 내보내기
- 로그인 전 공개 상태 안내, 스크립트 문자열 무해화, 비밀값 노출 점검

### T07 · 인증 및 접근 제어

> T06 다이어리에 계정 인증과 서버 측 소유권 검사를 추가해 사용자별 자료를 분리하는 보안 확장 프로젝트

최종 T06 프로젝트를 그대로 이어서 가입·로그인·로그아웃, 비밀번호 해시 저장, 서버 세션, 사용자별 자료 소유권 검사를 추가했습니다. 화면에서 숨기는 것에 그치지 않고 서버가 로그인 사용자를 기준으로 조회·수정·삭제 권한을 판단하도록 구현했으며, 서로 다른 계정 간 접근이 실제로 거절되는지 양방향으로 검증했습니다.

**주요 내용**
- 직접 구현 방식 + Cloudflare Workers Web Crypto API 사용
- `PBKDF2-HMAC-SHA-256` + 계정별 랜덤 salt로 비밀번호 저장
- 같은 비밀번호를 사용한 두 계정의 저장 해시가 서로 다름을 확인
- 서버 저장형 opaque session과 `HttpOnly`·`SameSite=Strict`·`Secure` 쿠키 사용
- 12시간 세션 만료, 로그아웃 및 비밀번호 변경 시 기존 세션 폐기
- 로그인하지 않은 보호 API 요청은 401, 다른 사용자 자료 ID 요청은 404 처리
- 읽기·수정·삭제를 계정 A→B / B→A 양방향으로 검증
- URL·헤더·본문의 임의 사용자 정보는 인증 근거로 사용하지 않고 세션의 사용자 ID만 신뢰
- T06 기존 자료를 첫 계정으로 이전
- 실제 5일 사용 기록과 Day 2 뒤 / Day 3 앞 계획 규칙 1회 변경
- 같은 지표·단위·계산 규칙으로 변경 전후 비교 및 합계·평균 직접 대조
- 전체 자료 내보내기, 계정 삭제, 인증 구현 설명서와 검증 절차 작성
- rate limiting·비밀번호 재설정·MFA 등 아직 구현하지 못한 항목과 위험 기록

**5일 사용 기록 요약**
- 질문: 계획 규칙을 바꾸면 하루 ALEPT 과제 실제 집중 시간이 늘어나는가?
- 지표: ALEPT 과제 실제 집중 시간 / 단위: 분
- 기록: 85 → 70 → 40 → 50 → 65분
- 합계: 310분 / 평균: 62분
- 규칙 변경 전 평균: 77.5분 / 변경 후 평균: 51.7분

### T08 · 패스키 비공개 공간

> T01의 공개 자기소개 페이지는 그대로 유지하면서, WebAuthn 패스키로만 들어갈 수 있는 개인 비공개 영역을 추가하는 프로젝트

T01의 공개 영역과 별도로 비공개 자료 공간을 만들고, 비밀번호 대신 패스키의 공개키·challenge·서명 검증을 이용해 접근을 제어하는 과제입니다. 화면에서 단순히 숨기는 방식이 아니라 로그인하지 않은 요청에 비공개 내용 자체를 내려주지 않도록 서버에서 차단해야 합니다.

**구현 목표**
- T01 공개 소개 페이지 유지 + 비공개 항목 3개 이상의 별도 영역 구성
- 비로그인 상태에서 비공개 화면·직접 서버 요청 모두 차단
- 등록 요청마다 새로운 challenge 생성 및 서버 보관
- 서버에는 공개키만 저장하고 개인키는 기기 밖으로 전송하지 않음
- 패스키 등록 취소 시 서버 데이터가 남지 않도록 처리
- 로그인마다 새로운 challenge를 발급하고 저장된 공개키로 서명 검증
- 이미 사용한 challenge 재사용 요청 거절
- 비밀번호 입력 없이 세션 또는 토큰으로 로그인 상태 유지
- 한 계정에 패스키 2개 등록, 이름·등록일 표시, 삭제 후 남은 패스키로 로그인 검증
- 계정 2개 사이 비공개 자료 접근 차단 및 다른 계정 정보 위조 요청 검증
- 등록·로그인·로그아웃·비공개 자료 조회의 소스 흐름과 인증 구현 설명서 작성
- 아직 막지 못한 위험 요소를 최소 1개 이상 구체적으로 기록

## ✅ 개발 및 검증 원칙

1. **직접 검증:** 화면에 보이는 결과뿐 아니라 요청·응답·저장 데이터까지 직접 확인합니다.
2. **재현 가능한 기록:** 입력·기대값·결과·수정 전후·실행 순서를 남겨 같은 검사를 다시 수행할 수 있게 합니다.
3. **실패 상황 확인:** 정상 동작만 확인하지 않고 오류·손상·권한 거절·복구 상황을 의도적으로 재현합니다.
4. **데이터 보존과 근거 연결:** 화면의 집계나 결과가 어떤 저장 기록에서 나왔는지 다시 확인할 수 있게 합니다.
5. **공개 범위와 보안 점검:** 개인정보·비밀번호·토큰·API 키 등 비밀값이 화면·배포 파일·네트워크·Git 기록에 노출되지 않도록 검사합니다.
6. **서버 측 권한 검증:** 비공개 자료는 화면에서 숨기는 것에 그치지 않고 서버가 실제 접근 권한을 확인하도록 합니다.
7. **AI 활용 구분:** AI에게 맡긴 일, 직접 판단한 일, AI 제안을 따르지 않은 일을 구분해 기록합니다.
8. **결과 중심 개선:** 느낌이 아니라 플레이 기록·테스트 결과·사용 기록·측정값을 근거로 변경 이유를 설명합니다.
