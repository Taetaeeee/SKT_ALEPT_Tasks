# SKT ALEPT Tasks

> AI를 활용하여 웹 서비스를 구현하고, 직접 테스트한 결과를 바탕으로 개선 과정을 기록하는 실습 프로젝트 모음입니다.

## 🧩 과제별 프로젝트

### T01 · 자기소개 페이지

> 경험과 강점을 구체적인 근거와 함께 소개하는 1페이지 웹사이트

공개할 정보와 비공개 정보를 구분하고, 경험을 상황·행동·결과 중심으로 정리했습니다. 서로 다른 PC 해상도에서 화면을 확인하고 링크, 키보드 접근성, 콘솔 오류 등을 점검했습니다.

**주요 내용**
- 자기소개·활동·근거를 한 화면에 정리
- 공개 범위 및 개인정보 점검
- PC 해상도별 레이아웃과 접근성 검증
- 발견한 결함의 수정 전후 기록

**링크:** [🌐 페이지 실행](https://taetaeeee.github.io/SKT_ALEPT_Tasks/T01_onepagemyself/) · [📁 소스 코드](./T01_onepagemyself/)

### T02 · 암호 해제 미니게임

> 제한시간 안에 코드를 해제하는 반응형 웹 게임

25초 제한시간 동안 코드 입력을 반복하는 미니게임입니다. 일시정지와 재시작, 창 크기 변경과 포커스 복귀 등 상태 관리를 점검했습니다. 목표 7자리·8자리 설정을 각각 10회 플레이한 결과를 비교하여 최종 난이도를 선택했습니다.

**주요 내용**
- 제한시간 25초, 게임 진행에 따른 코드 길이 변화
- 게임 일시정지·재개·재시작
- 빠른 연속 입력과 장시간 실행 안정성 테스트
- 동일 조건 총 20회 플레이를 통한 난이도 검증

**링크:** [🌐 게임 실행](https://taetaeeee.github.io/SKT_ALEPT_Tasks/T02_code_break/) · [📁 소스 코드](./T02_code_break/)

### T03 · 밈 만들기

> 이미지에 여러 문구를 자유롭게 배치하고 PNG로 저장하는 웹 편집 도구

이미지를 불러와 문구의 위치·크기·색상·각도를 조절하고, 미리보기 결과를 이미지 파일로 저장할 수 있도록 구현했습니다. 이미지와 문구의 위치 조절, 다양한 출력 비율, 입력 오류 처리 등을 확인했습니다.

**주요 내용**
- PNG·JPEG 이미지 불러오기 및 Drag & Drop
- 다중 문구 편집, 위치 이동 및 회전
- 이미지 위치 조절과 실시간 미리보기
- 1:1·4:5·9:16 화면비 및 PNG 저장
- 템플릿 관리와 극단 입력 검증

**링크:** [🌐 편집기 실행](https://taetaeeee.github.io/SKT_ALEPT_Tasks/T03_card_studio/) · [📁 소스 코드](./T03_card_studio/)

### T04 · 생활 환율

> 제 환율 정보의 출처와 조회 시각을 확인하고 날짜별로 기록하는 정보 보드

USD·JPY·CNY 환율을 실제 공개 데이터에서 조회하고, 조회 시각과 출처 시각을 구분해 표시했습니다. 외부 응답 실패 시 마지막 정상값을 보존하고 다시 시도할 수 있도록 구현했습니다. 서로 다른 KST 날짜의 실제 기록을 비교하여 전일 대비 변화를 검증했습니다.

**주요 내용**
- USD·JPY·CNY 환율 조회
- 출처·단위·관측 시각·조회 시각 표시
- KST 기준 날짜별 기록과 전일 대비 비교
- Timeout·응답 거절·호출 제한·오프라인·형식 변경 테스트
- 마지막 정상값 유지 및 복구 시나리오

**링크:** [🌐 보드 실행](https://taetaeeee.github.io/SKT_ALEPT_Tasks/T04_exchange_board/) · [📁 소스 코드](./T04_exchange_board/)

### T05 · AI 협업 및 인수인계

> 고정된 검사를 기준으로 서로 다른 AI의 작업과 인수인계 과정을 비교하는 실험

T03의 기능 개선을 대상으로 작업 전 동일한 테스트 10개와 사용 상한을 설정합니다. AI A의 중간 결과를 저장소와 인수인계 문서로 전달한 다음, AI B가 기존 대화 없이 작업을 이어받아 완성하는 과정을 검증합니다.

**주요 내용**
- 작업 전 입력·기대값이 있는 테스트 10개 고정
- AI A 작업 결과 및 인수인계 문서 작성
- AI B의 동일 조건 테스트 및 기능 완성
- 작업시간·호출 수·오류 회차·통과 수 비교

**링크:** [📊 결과 보고서](https://taetaeeee.github.io/SKT_ALEPT_Tasks/T05_handoff_project/report.html) · [📁 소스 코드](./T05_handoff_project/)

### T06 · 계획·실행 다이어리

> 계획과 실제 수행 결과를 함께 기록하고 회고하는 웹 애플리케이션

Cloudflare Workers와 D1(SQLite)을 사용해 계획, 할 일, 실행 기록, 돌아보기를 서버 데이터베이스에 저장하도록 구현했습니다. 계획 수정 전 내용을 보존하고, 실제 소요시간과 막힌 이유를 계획값과 별도로 기록하며, 집계 숫자에서 근거 기록까지 다시 확인할 수 있게 구성했습니다.

**주요 내용**
- 계획 작성 및 수정 이력 관리
- 할 일 생성·수정·완료와 검색·필터·정렬
- 실제 작업시간과 막힌 이유를 별도 실행 기록으로 관리
- 예상 시간과 실제 시간 비교, 돌아보기 및 다음 계획 반영
- 서버 데이터베이스를 이용한 기록 보존과 자료 내보내기

**링크:** [📁 소스 코드](./T06_pds_diary/)

### T07 · 인증 및 접근 제어

> T06 계획·실행 다이어리를 계정별로 보호하도록 확장한 프로젝트

T06에서 구현한 다이어리를 기반으로 계정 인증과 접근 제어 기능을 추가했습니다. 로그인 상태를 관리하고, 다른 계정의 자료에 접근하지 못하도록 서버에서 권한을 검사하는 구조로 확장했습니다.

**주요 내용**
- 회원가입·로그인·로그아웃 흐름
- 비밀번호 보관 및 로그인 세션 관리
- 계정별 자료 접근 제어와 권한 검증
- 기존 T06 자료를 계정과 연결하는 데이터 구조
- 인증 구현 설명과 접근 차단 검증 기록

**5일 사용 기록 요약**
- 질문: 계획 규칙을 바꾸면 하루 ALEPT 과제 실제 집중 시간이 늘어나는가?

- 기록: 85 → 70 → 40 → 50 → 65분
- 합계: 310분 / 평균: 62분
- 규칙 변경 전 평균: 77.5분 / 변경 후 평균: 51.7분

### T08 · 패스키 비공개 공간

> T01 소개 페이지의 공개 영역은 그대로 유지하고, MY SPACE만 패스키로 보호하는 WebAuthn 인증 프로젝트

T01의 자기소개 내용을 누구나 볼 수 있도록 유지하면서, 별도의 비공개 작업실을 추가했습니다. 비밀번호 대신 기기에 저장된 패스키로 로그인하고, 서버에서 일회용 Challenge와 공개키 서명을 검증한 뒤 인증된 계정의 자료만 제공합니다. 실제 개인정보 대신 가상 계정과 가상 자료를 사용했습니다.

**구현 목표**
- 공개 소개 영역과 패스키 보호 MY SPACE 영역 분리
- WebAuthn 등록·로그인, 공개키 저장, Challenge 재사용 차단
- Cloudflare Workers·D1 기반 서버 세션 관리 및 로그아웃 후 재사용 거절
- 계정별 비공개 자료 조회와 타 계정 자료 접근 차단
- 패스키 2개 등록, 하나 삭제 후 남은 패스키로 재로그인 검증
- 비로그인 HTTP 401, 타 계정 자료 요청 HTTP 404 및 서명 변조 거절 검증

**링크:** [🌐 공개 소개 / MY SPACE 실행](https://t08-passkey-myspace.nalzzoaleph26.workers.dev/) · [📁 소스 코드](./T08_passkey_myspace/) · [📄 인증 구현 설명서](./T08_passkey_myspace/AUTH_EXPLANATION.md) · [✅ 검증 기록](./T08_passkey_myspace/evidence/T08_FINAL_VERIFICATION.md)

> **심사 안내:** 공개 소개 페이지는 로그인 없이 열립니다. 비공개 자료를 확인하기 위한 패스키 등록이나 로그인은 심사자에게 요구하지 않습니다.

## 🔗 프로젝트 간 연계

## ✅ 개발 및 검증 원칙

1. **직접 검증:** 화면에 보이는 동작과 저장된 결과를 함께 확인합니다.
2. **재현 가능한 기록:** 테스트 입력·기대값·결과와 오류 수정 전후를 기록합니다.
3. **공개 범위 점검:** 개인정보 및 비밀키가 공개 저장소와 배포 파일에 포함되지 않도록 검사합니다.
4. **AI 활용 구분:** AI에게 맡긴 작업과 직접 판단한 내용을 구분합니다.
5. **결과 중심 개선:** 사용 기록과 테스트를 바탕으로 변경 이유를 설명합니다.
