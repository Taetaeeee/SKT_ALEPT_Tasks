## 3. 재현·통과 확인 4가지
- 위치: 공개 결과물 주소의 첫 화면에서 시작합니다.
- 행동: ① `대표 경험 보기`를 선택합니다. ② DB 설계 경험의 `공개용 ERD 보기`를 엽니다. ③ ABOUT ME의 `취향을 조금 더 보기`를 마우스 또는 Tab+Enter/Space로 실행합니다.
- 통과 모습: 경험 영역으로 이동하고 실제 SQL을 기준으로 정리한 ERD가 펼쳐지며, 취향 영역에 보유 카메라와 직접 촬영한 사진이 표시됩니다.
- 안 될 때 모습: 경험 영역으로 이동하지 않거나, ERD·취향 영역이 열리지 않거나, 키보드로 같은 상호작용을 실행할 수 없습니다.

## 4. AI와 나의 판단 3줄
- AI에게 맡긴 일: 과제 통과 기준을 바탕으로 페이지 구조와 HTML/CSS/JavaScript 초안, 접근성 점검, 경험별 설명과 공개 근거 정리를 맡겼습니다.
- 직접 판단한 일: 업무 자동화·DB 설계·Hyperledger 트러블슈팅을 대표 경험으로 정하고, 공개할 취향과 사진, 문장 표현, 공개·비공개 범위와 최종 디자인을 직접 선택했습니다.
- AI 제안을 따르지 않은 일: 추가 색상 테마는 기존의 단순한 디자인이 더 적합하다고 판단해 적용하지 않았고, 중복된 상단 취향 버튼과 불필요한 footer도 제거했습니다.

## 5. 실제 결함 수정 전후
1. 수정 전: 페이지 목적은 있었지만 누구에게 보여주는 페이지인지 대상이 명확하지 않았습니다.
   수정 후: `저를 처음 알게 된 사람에게`라는 대상을 넣어 대상과 목적을 한 문장에 함께 표시했습니다.
2. 수정 전: 초기 취향 토글에서 `aria-expanded` 값과 `hidden` 상태가 맞지 않아 영역이 정상적으로 열리지 않았습니다.
   수정 후: 두 상태를 함께 변경하도록 로직을 수정해 마우스와 키보드에서 동일하게 동작하도록 했습니다.
3. 수정 전: 공개할 정보와 공개하지 않을 정보가 한곳에 정리되어 있지 않았습니다.
   수정 후: PUBLIC EVIDENCE 하단에 공개 5개 항목과 비공개 5개 항목을 구분해 표시했습니다.
4. 수정 전: 03 경험 미리보기의 `권한` 표현과 실제 트러블슈팅 내용의 `파일 형식` 표현이 달랐습니다.
   수정 후: `로그·인증서·파일 형식`으로 표현을 통일했습니다.
5. 수정 전: 초기 공개용 ERD와 Fabric 구성 이미지에 실제 코드와 다른 예시 필드·코드가 포함되어 있었습니다.
   수정 후: 실제 `create_table.sql`, `submit_mapping.py`, `ascii_mapping_chaincode.go`, `compose-test-net.yaml`을 기준으로 공개 근거를 다시 작성했습니다.

## 6. 제출 직전 확인
- 1366×768 첫 화면에 소개·활동·근거가 함께 보이는지
- 1920×1080 첫 화면에 소개·활동·근거가 함께 보이는지
- 두 해상도에서 가로 넘침이 없는지
- 모든 공개 링크가 선언한 주소로 열리는지
- Tab 이동과 Enter/Space 상호작용이 정상인지
- 제목 단계가 h1 → h2 → h3 순서를 유지하는지
- 일반 본문 텍스트 대비가 4.5:1 이상인지
- 브라우저 콘솔 빨간 오류가 0건인지
- 결과물 URL과 소스 URL이 새 시크릿 창에서 로그인 없이 열리는지
- 공개 저장소의 전체 Git 기록에 비밀번호·토큰·API Key·인증서 원문이 없는지
